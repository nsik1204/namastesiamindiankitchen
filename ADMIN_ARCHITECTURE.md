# Namaste Siam Indian Kitchen — Complete Admin Architecture Blueprint

This document houses the blueprint for a ready-to-implement, robust, enterprise-grade Admin Panel and back-end integration module. It is engineered to support seamless future **Supabase** or alternative PostgreSQL integration.

## 2. Database Schema Planning

Below is the complete entity relationship modeling designed for **PostgreSQL** or **Supabase**. It maps core features with rich metadata, status metrics, and tracking defaults.

```sql
-- 1. Enable secure uuid generation
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. RESTAURANT SETTINGS
CREATE TABLE restaurant_info (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name VARCHAR(255) NOT NULL,
  address TEXT NOT NULL,
  phone VARCHAR(50) NOT NULL,
  opening_hours TEXT NOT NULL,
  instagram VARCHAR(100),
  website VARCHAR(100),
  dining_style VARCHAR(150),
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 3. INTERACTION & CHAT PLUGINS (WhatsApp & LINE Integration)
CREATE TABLE chat_integrations (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  whatsapp_number VARCHAR(50),
  whatsapp_default_message TEXT,
  line_id VARCHAR(100),
  line_qr_url TEXT,
  is_active BOOLEAN DEFAULT true,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 4. BRAND STORY & HIGHLIGHT REELS
CREATE TABLE brand_story (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  story_paragraphs TEXT[] NOT NULL,
  highlights TEXT[] NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 5. MENU CATEGORIES
CREATE TABLE categories (
  id VARCHAR(50) PRIMARY KEY, -- Slug identifier matching custom category codes
  label VARCHAR(100) NOT NULL,
  sort_order INT DEFAULT 0,
  is_visible BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 6. FOOD & BEVERAGES CATALOGUE
CREATE TABLE dishes (
  id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  price_thb NUMERIC(10, 2) NOT NULL,
  category VARCHAR(50) REFERENCES categories(id) ON UPDATE CASCADE,
  food_type VARCHAR(20) CHECK (food_type IN ('veg', 'nonveg')) DEFAULT 'veg',
  spice_level VARCHAR(50) DEFAULT '🌶 Mild',
  ingredients VARCHAR(100)[],
  chef_special BOOLEAN DEFAULT false,
  bestseller BOOLEAN DEFAULT false,
  customer_favorite BOOLEAN DEFAULT false,
  today_special BOOLEAN DEFAULT false,
  image_url TEXT NOT NULL,
  is_available BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 7. AMBIENCE & GALLERY COLLAGES
CREATE TABLE gallery (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  image_url TEXT NOT NULL,
  alt_text VARCHAR(255) NOT NULL,
  is_tall BOOLEAN DEFAULT false,
  sort_order INT DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

## 3. API & Controller Routing Planning

To support server-side state or RESTful API wrappers, we plan the following secure REST design structure:

### Client-Side Gateway (Public Reads)
*   `GET /api/v1/restaurant` : Fetch overall restaurant metadata, hours, and addresses.
*   `GET /api/v1/menu` : Pulls categories, active and available foods, and highlights.
*   `GET /api/v1/gallery` : Pulls images with sizing parameters for rendering.

### Administrative Control Gateway (Authenticated Mutators)
*   `POST /api/v1/auth/login` : Receives payload `(email, password)` and replies with a secure JWT.
*   `PUT /api/v1/admin/settings` : Changes core address, branding, line or whatsapp tokens.
*   `POST /api/v1/admin/categories` : Append new menu columns, sorting weights.
*   `PUT /api/v1/admin/categories/:id` : Edit categories attributes.
*   `DELETE /api/v1/admin/categories/:id` : Demotes or re-routes existing linked items safely.
*   `POST /api/v1/admin/dishes` : Inserts chef entrees, tags, and pricing parameters.
*   `PUT /api/v1/admin/dishes/:id` : Mutates specs, pricing, and tag arrays (dynamic ingredients text fields).
*   `DELETE /api/v1/admin/dishes/:id` : Archives or purges items.

## 4. Security Planning & Row-Level Access (RLS)

Integrating secure schemas involves locking direct operations. We design a strict system containing the following paradigms:

### Sub-System Access Policies (Row-Level Security)
By configuring Postgres/Supabase RLS layers, we block unauthenticated data mutation:

```sql
-- Lock down all tables by default
ALTER TABLE restaurant_info ENABLE ROW LEVEL SECURITY;
ALTER TABLE chat_integrations ENABLE ROW LEVEL SECURITY;
ALTER TABLE brand_story ENABLE ROW LEVEL SECURITY;
ALTER TABLE categories ENABLE ROW LEVEL SECURITY;
ALTER TABLE dishes ENABLE ROW LEVEL SECURITY;
ALTER TABLE gallery ENABLE ROW LEVEL SECURITY;

-- 1. Create Public Select Access Policies
CREATE POLICY "Allow public SELECT access to restaurant info" 
  ON restaurant_info FOR SELECT USING (true);

CREATE POLICY "Allow public SELECT access to categories" 
  ON categories FOR SELECT USING (true);

CREATE POLICY "Allow public SELECT access to dishes" 
  ON dishes FOR SELECT USING (true);

-- 2. Create Restrictive Administrator Write Access Rules
CREATE POLICY "Allow authenticated staff update restaurant info"
  ON restaurant_info FOR ALL TO authenticated
  USING (true) WITH CHECK (true);

CREATE POLICY "Allow authenticated staff modify dishes catalog"
  ON dishes FOR ALL TO authenticated
  USING (true) WITH CHECK (true);
```

### Sanitization, Guardrails, and Middleware
1.  **JSON Validation Schema**: All body elements run through strict validation algorithms checks (e.g. `zod` schema constraints) before touching query targets to eliminate SQL injection threat risks.
2.  **Asset Guarding & Sandbox Filters**: All generated user coordinates, links, web targets, phone layouts undergo sanitization against cross-site scripting (XSS).

## 5. CRUD Management & Operation States

Managing items dynamic changes involves setting up strict UI states:

### Status Transitions
Operating on dishes utilizes transparent transactional flows for seamless experience feedback:
1.  **Read/Select State**: Beautiful visual grids with state metrics.
2.  **Creation/Update Form**: Slide out forms holding options such as image selector, tags, pricing, and ingredient list compilers.
3.  **Submit State**: Spinning indicators, button states locked to mock concurrent post failures.
4.  **Error States**: Graceful toaster modules informing when connection fails, price is negative, or validation bounds are missed.

### Image Optimization Pipelines
All images are hosted and delivered via high-capacity content distribution networks (CDN) to preserve performance scores while avoiding processing overhead on local storage instances.
